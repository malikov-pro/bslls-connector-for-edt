# Готово к установке (финальный чек-лист)

Пройти сверху вниз, **останавливаться на первом красном**. Зелёный нижний ярус
не доказывает верхний: «собралось» ≠ «работает в EDT». Подробности механики —
`bslls-build-test`; карта кода — `bslls-architecture`.

## Ворота

1. **Гигиена diff'а**
   - `git status`/`git diff`: нет мусора (`target/`, `bin/`, временных файлов),
     diff читается ровно как задуманное изменение.
   - Если менялся v8std или `scripts/generate-ls-checks.py` — регенерация
     каталога выполнена и её артефакты (plugin.xml, tsv) входят в diff
     осознанно; карточки `check.descriptions/` в git не попадают.
   - Правок сгенерированного руками нет.

2. **Сборка** — `bash compile.sh` → BUILD SUCCESS, zip со свежим квалификатором.
   Для ветки 2026.1 дополнительно: `bash compile.sh --profile edt-2026.1`.
   Симптом-маркер: ошибки XML-entity = сборка запущена мимо `connector/.mvn/jvm.config`.

3. **Контракты из CLAUDE.md** — глазами по diff'у:
   `[BSL LS] ` префикс на месте; версии пакетов в MANIFEST.MF не зафиксированы;
   regex регионов `BSLLS:` не тронут без прогона обоих форматов; правки строки
   `//@skip-check` удаляют только коды LS.

4. **README обновлён**, если менялось видимое поведение: установка, режимы
   запуска, настройки, сборка.

5. **Живая установка (главное доказательство)**
   - Закрыть тестовую EDT, затем `bash scripts/deploy-edt.sh`
     (снимает старую копию, ставит свежую, проверяет `bundles.info`).
   - Anti-stale: в выводе скрипта — квалификатор из последней сборки;
     сверить с именем p2-zip. Не совпало → сборка была до изменений, пересобрать.

6. **Дымовой сценарий в EDT** (для изменений поведения):
   - `Окно → Параметры → Коннектор BSL LS`: страница открывается, статус LS
     поднимается (или честная ошибка без LS).
   - Сохранить BSL-модуль с нарушением (например, длинную строку для
     `LineLength`) → замечание `[BSL LS] …` в панели `Проблемы конфигурации`.
   - «Подавить» у проверки LS → в модуле появился `//@skip-check` только с кодом
     LS; повторить на типовой проверке EDT — её код не тронут.
   - «Открыть проверку» → карточка диагностики открылась.
   - Трогали рестарт (`LSService`)? Переключить режим native/jar туда-
     обратно, убедиться, что подключение восстанавливается.

7. **Чистое дерево + локальный коммит** — адверсариально перечитать diff,
   закоммитить локально. Push и деструктивные действия — только по явной просьбе.

## Быстрое «определение готовности»

- [ ] diff чист, генерация актуальна
- [ ] `compile.sh` зелёный (+ профиль 2026.1, если затрагивал платформу)
- [ ] контракты CLAUDE.md соблюдены
- [ ] README соответствует поведению
- [ ] установлен свежий бандл в EDT (anti-stale)
- [ ] дымовой сценарий пройден
- [ ] локальный коммит сделан
