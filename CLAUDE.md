# bslls-connector-for-edt — кодекс проекта (карта минных полей)

Плагин для 1С:EDT (Maven/Tycho, Eclipse OSGi): включает проверки
[BSL Language Server](https://github.com/1c-syntax/bsl-language-server) в EDT.
Этот файл — **чего НЕ делать** и **где остановиться и подумать дважды**.
«Как делать правильно» — в скиллах `.claude/skills/`. Claude Code загружает файл
автоматически; opencode — из AGENTS.md.

---

## 📚 Скиллы (загружай нужный перед работой — `.claude/skills/`)

- `bslls-build-test` — сборка, установка p2 в EDT, проверка результата.
- `bslls-architecture` — карта бандла: пакеты, каналы замечаний, кто за что отвечает.
- `bslls-new-check` — как добавляется/обновляется каталог диагностик (всё генерируется).
- `bslls-ready-to-deploy` — финальные ворота перед «готово»/коммитом.

## ❌ Жёсткие «нельзя» (нарушение = баг или сломанная сборка)

1. **Сгенерированное руками не править.** Каталог проверок в `plugin.xml`
   (`<check>`-записи, ~187 шт.), карточки `check.descriptions/` (git-ignored) и
   ресурс `check/LsDiagnosticCatalog` → `ls-diagnostics.tsv` пишет скрипт
   `scripts/generate-ls-checks.py` из сабмодуля `third_party/v8std`.
   Ручная правка будет затёрта следующей регенерацией.
2. **Один исходник на две версии EDT — версии пакетов в `MANIFEST.MF` не
   фиксировать** (`Require-Bundle` без `bundle-version`). Различия платформ:
   LSP4J 0.23.1 (EDT 2025.2) vs 1.0.0 (EDT 2026.1). Не использовать API,
   которого нет в 0.23.1, без явной оговорки о профиле edt-2026.1.
3. **Префикс `[BSL LS] ` обязателен** в тексте замечаний обоих каналов —
   константа `LsDiagnosticCatalog.MESSAGE_PREFIX`. По нему замечание LS нельзя
   спутать с типовым сообщением EDT; тестов на это нет, контракт держится на коде.
4. **Регионы подавления** `// BSLLS:Код-off … -on`, глобальные
   `// BSLLS:off … -on` — единственный regex в `LsSkipCheck.BSLLS_TOGGLE`
   (регистронезависимый). Менять только вместе с прогоном обоих форматов.
5. **«Подавить» в EDT:** EDT всегда вставляет `//@skip-check <код>`. Коннектор
   обязан убирать из этой строки **только коды LS**
   (`LsSuppressionComments.looksLikeSkipCheckInsert`,
   `removeLsCodesFromSkipLine`) и никогда не трогать типовые коды EDT.
6. **lombok вне IDE работает только через javaagent:**
   `-javaagent:<путь>/lombok.jar=ECJ` в `MAVEN_OPTS`
   (`tycho-compiler-plugin` аннотации не обрабатывает). Симптом пропажи агента —
   «cannot find symbol» на геттерах/билдерах. Канонический путь — `compile.sh`,
   MAVEN_OPTS вручную не изобретать.
7. **XML-entity лимиты уже в `.mvn/jvm.config`** — Maven подхватывает их сам
   (склеивает с MAVEN_OPTS). Дублировать в env не нужно.

## 🛑 Зоны «стоп и подумай дважды» (большой радиус поражения)

| Где | Почему опасно | Перед правкой |
|---|---|---|
| `service/LSService.java` | Жизненный цикл процесса LS (`start/stop/restart/ensureStarted`, все `synchronized`); рестарт дергается из настроек и статуса | Проверить сценарии рестарта при смене режима (native/jar/websocket) |
| `listener/*` (`LsSkipCheckRewriter`, `PageEventListener`, `WindowEventListener`) | Реагируют на правки редактора пользователя и правят строку `//@skip-check` в его модуле на диске | Прогнать ручной сценарий «Подавить» на известном коде LS и на типовом коде EDT |
| `lsp/WebSocketLspTransport.java`, `BSLConnector.java` | Транспорт к LS; WebSocket не использует кэш и GitHub | Помнить: слоты кэша есть только у native/jar |
| Смена формата релизов GitHub (`util/GitHubReleases.java`) | Выбор релиза в настройках + скачивание в `~/.bsl-connector-for-edt` (один слот на режим) | Свериться со структурой assets реального релиза BSL LS |

## ⚠️ Известные ловушки окружения

- **Установка p2 из архива:** флажок «Обращаться во время инсталляции ко всем
  сайтам обновления…» должен быть **снят**, иначе p2 лезет на `services.1c.dev`
  (ошибка аутентификации), а локальные артефакты не находит.
- **«Все элементы установлены»** = в zip тот же квалификатор, что уже стоит.
  Пересоберите (`bash compile.sh`) или удалите фичу в
  `Справка → О программе → Сведения об установке` и ставьте заново.
- **JAR-режим требует Java 21+** для BSL LS 1.x (JVM EDT 17 не подходит);
  команда Java берётся из PATH.
- Учётные данные репозитория EDT — `bom/settings.xml` +
  `bom/edt-credentials.env` (в CI — секреты `MAVEN_USERNAME` /
  `MAVEN_CENTRAL_TOKEN`). Никогда не коммитить реальные значения.

## 🧪 Уровни проверки (знать, что доказывает какой)

- **Ярус 0 — сборка:** `bash compile.sh` → BUILD SUCCESS + свежий квалификатор
  в имени zip. Механика: скилл `bslls-build-test`.
- **Ярус 1 — юнит-тесты (Tycho test-фрагмент):** планируется; чистая логика —
  регионы подавления, маппинг CamelCase↔dash-case, каталог диагностик.
- **Ярус 2 — живая установка:** установить p2 в EDT 2025.2, убедиться в панели
  `Проблемы конфигурации` и карточке диагностики. Единственное доказательство
  поведения в EDT.
- **Ярус 3 — e2e в CI (headless EDT через `p2 director`):** план; референс —
  `_source/EDT-MCP/.github/actions/setup-edt`.

Зелёный нижний ярус НЕ доказывает верхний.
